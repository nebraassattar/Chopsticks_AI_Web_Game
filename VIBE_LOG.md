Vibe-Coding Development Log

This log records five meaningful uses of an AI coding assistant. It summarizes
the interactions instead of reproducing the complete conversation.

Interaction 1 - Understanding Minimax

Prompt:
Explain how the unfinished best_move_dp() function should use the given
Player-A scoring system, terminal states, and backward traversal.

AI suggestion:
Initialize every state at the maximum depth, then process levels in reverse.
Use the maximum successor value on A's even-numbered turns and the minimum on
B's odd-numbered turns. Store both the chosen value and successor state.

What I accepted or changed:
I accepted the bottom-up structure and added explicit handling for terminal
states at every earlier level, not only at the maximum depth.

What I learned / how I verified it:
I learned that successors must already be stored before a parent is evaluated.
I verified the three terminal values, MAX/MIN behavior, table size, and that
every stored successor was legal.

Interaction 2 - Designing One Shared Move Engine

Prompt:
How can I support clickable attacks and redistribution choices without
duplicating the rules in the interface?

AI suggestion:
Return move objects from one generateLegalMoves() function. Each object should
include the move type, attack source/target or redistribution details, and the
complete next state. Both the UI and minimax can consume the same output.

What I accepted or changed:
I accepted the move-object design. I kept equivalent attacks separately
clickable but added uniqueSuccessorStates() so minimax evaluates identical
successor states only once, like the Python set.

What I learned / how I verified it:
I learned how metadata can support presentation without becoming a second game
engine. I compared selected A-turn and B-turn outputs against the Python
reference and tested attacks, redistributions, terminal states, and invariants.

Interaction 3 - Translating Dynamic Programming to JavaScript

Prompt:
Help translate the verified Python dynamic-programming/minimax approach into a
separate ai.js module.

AI suggestion:
Use a JavaScript Map keyed by all four hand values and the level. Construct
all 625 configurations at each level, store { value, nextState }, and expose a
function that maps the selected successor back to a legal move object.

What I accepted or changed:
I accepted the separate AI module and deterministic tie-breaking. I kept all
attack and redistribution generation in game.js so ai.js contains no copied
rules.

What I learned / how I verified it:
I learned why the state key must include the level in a depth-limited search. I
verified the 13,125-entry depth-20 table, checked the minimax recurrence, and
confirmed that every selected move was generated by the game engine.

Interaction 4 - Building the Playable Interface

Prompt:
Connect the tested engine and AI to a single-page interface with direct attacks,
redistribution, player-order selection, restart, and game-over handling.

AI suggestion:
Use button elements for each hand, highlight the selected source and legal
targets, generate redistribution buttons from legal move objects, and permit
state changes only through an applyMove() function that revalidates the move.

What I accepted or changed:
I accepted the interaction flow and responsive layout. During review, I added
cancellation of pending computer timers so restarting cannot allow a delayed
move from an old match to affect a new game.

What I learned / how I verified it:
I learned that UI disabling alone is not sufficient protection; the controller
should revalidate every transition. I reran the engine and AI tests after adding
the UI and checked all JavaScript selectors against the HTML element IDs.

Interaction 5 - Explaining and Testing the AI

Prompt:
Add a show/hide educational panel that lists the current computer state, its
MAX/MIN role, legal moves, minimax values, selected move, and predicted outcome.

AI suggestion:
Expose an analyzePosition() result from ai.js using the existing table and
legal-move generator. Preserve the most recent computer decision so the user
can inspect it after the board updates.

What I accepted or changed:
I accepted the analysis object and displayed only distinct successors, matching
what minimax actually evaluates. I kept all formatting and DOM creation in the
browser controller rather than adding algorithmic rules to HTML.

What I learned / how I verified it:
I learned how to expose an algorithm's reasoning without recomputing it in the
view. Tests confirm A selects the maximum displayed value, B selects the
minimum, and exactly one move is marked selected. A final integration test also
simulates complete games for both human roles and checks the full depth-20
table.
